Seu próximo teste: publicação e banco

Quando me chamarA URL já existe; /api/health respondeu HTTP 503 em 01/10/2026.P0
  1. Abra a Cloudflare

    Entre em dash.cloudflare.com na sua própria sessão com 2FA. Procure Workers & Pages → projeto Linux Flow → Deployments. Confirme que o projeto é do tipo Pages, conectado ao repositório Jonathan-Eleodoro/linux-flow e à branch de produção esperada.

    EsperadoUm deployment recente mostra sucesso e fornece uma URL https://…pages.dev.
  2. Confira o build

    Em Settings → Builds & deployments (ou opção equivalente), confira Root directory na raiz/vazio, Build command npm run build e Build output directory dist. Não use npx wrangler deploy como comando de Pages. Se o deployment falhou, abra o log do commit mais recente e veja o diagnóstico.

    EsperadoO build termina e publica a pasta dist; não aparece erro de cwd ou de módulo node:crypto.
  3. Confira o D1

    No painel, abra Storage & databases → D1 e o banco do projeto. Se ainda não existir, crie-o e aplique sql/d1-schema.sql seguido das migrações sql/migrations/001-premium-approval.sql e sql/migrations/002-educator-access.sql, sql/migrations/003-financial-retention.sql e sql/migrations/004-ranking-synced.sql pelo Console D1 ou pelo comando do guia de publicação. Confira se as tabelas aparecem. Em Pages → Settings → Bindings, associe esse banco ao nome exato DB em Production e faça um novo deploy. Para Preview, use outro banco com o mesmo esquema.

    EsperadoBinding DB visível no ambiente correto; nenhuma chave de acesso copiada para o repositório.
  4. Teste a URL

    Abra a URL pública e depois acrescente /api/health. Pode também usar o comando abaixo no PowerShell, trocando apenas o domínio. Confira o código HTTP e a resposta.

    curl.exe -i https://SEU_PROJETO.pages.dev/api/health
    EsperadoHTTP 200 e {"status":"ready"}. 503 indica binding/esquema ausente ou indisponível; HTML em vez de JSON indica rota Functions não publicada.
  5. Teste a leitura sem dados reais

    Abra https://SEU_PROJETO.pages.dev/api/ranking?category=all&level=1&total=10. Num banco vazio, confira a lista vazia. Se houver registros de teste, a resposta pode conter ranking; não compartilhe dados pessoais.

    EsperadoJSON com a chave ranking e sem erro 503. Este passo confirma uma API funcional além do diagnóstico.
O que me enviar para analisar

A URL pública *.pages.dev, o estado do deployment (sucesso/falha), o código HTTP de /api/health e, se falhar, apenas as linhas do log com o erro. Oculte e-mail pessoal, tokens, códigos de perfil, QR Pix e dados de estudantes.

Segundo teste: fluxo com pessoas fictícias

A

Perfil e continuidade

Crie “Aluno Teste A” em Entrar → Criar, sincronize, faça um quiz e recarregue a página. O progresso deve voltar. Guarde o código de acesso só em local privado.

B

Ranking e privacidade

Ative a opção de compartilhar ranking, conclua um quiz e confira o apelido. Desative o compartilhamento e atualize o ranking: o perfil deve desaparecer imediatamente. Faça outra rodada sem compartilhar; depois apague o perfil.

C

Sala e permissões

Em outro navegador ou janela privada, crie “Aluno Teste B”. Entre numa sala criada por A. B pode responder, mas não iniciar/avançar nem ler logs do mestre.

D

Limpeza

Apague os dois perfis fictícios pela tela de dados. Confirme que o ranking não mantém os apelidos. Não use estudantes reais nesta rodada.
