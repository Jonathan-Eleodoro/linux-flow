Inicialize o D1 antes de cadastrar pessoas.

O Pages publicou o site, mas as APIs retornaram HTTP 503. A consulta feita no Console de linux-flow-db encontrou apenas _cf_KV, estrutura interna da Cloudflare: nenhuma tabela do Linux Flow foi criada. O próximo passo é aplicar o esquema e as cinco migrações em ordem.

O binding DB → linux-flow-db aparece no painel, mas o banco ainda não tem as tabelas da aplicação. Não crie perfis reais nem aceite Pix enquanto a API responder 503.

1. Descubra o estado do banco sem alterar dados

  1. Confira a publicação

    Entre na sua conta Cloudflare. Abra Workers & Pages → linux-flow → Deployments. Selecione a publicação de Production e confira o commit, a situação “Success” e o endereço linux-flow.pages.dev. Em Settings → Bindings, confirme DB → linux-flow-db em Production. Se alterou o binding após o último deploy, faça redeploy.

    EsperadoO commit da branch main foi publicado, e o binding aparece no ambiente Production.
  2. Confira o inventário após as migrações

    Você já consultou o banco vazio: apenas _cf_KV apareceu. Após a seção 2, volte a Storage & databases → D1 → linux-flow-db → Console, cole a linha inteira e clique em Execute. Ela lê apenas nomes de estruturas, sem perfis ou pagamentos.

    SELECT type, name FROM sqlite_master WHERE type IN ('table', 'trigger', 'index') AND name NOT LIKE 'sqlite_%' ORDER BY type, name;
    EsperadoAlém de _cf_KV, as 20 tabelas e 14 gatilhos do aplicativo devem estar presentes. Outras estruturas podem aparecer. Se alguma etapa SQL falhar, pare antes de executar a próxima.
  3. Confira as colunas alteradas

    No mesmo Console, execute PRAGMA table_info(pro_requests); e PRAGMA table_info(profile_results);. Procure confirmed_payment_reference na primeira tabela e verified na segunda. Compartilhe apenas os nomes das colunas. A 001 acrescenta confirmed_payment_reference e não deve ser repetida se a coluna já existe. Se a coluna, o índice e os gatilhos não concordarem, pare e registre a inconsistência antes de alterar o banco.

    EsperadoEstruturas da mesma migração presentes juntas, ou todas ausentes. O banco parcialmente migrado precisa de reparo específico.
  4. Se ainda houver 503, leia o diagnóstico privado

    Após o próximo deploy, abra Workers & Pages → linux-flow → Deployments → Production → View details → Functions e inicie os logs. Em outra aba, recarregue https://linux-flow.pages.dev/api/health. Procure Health unavailable com os totais de tabelas e gatilhos ou Health query failed com o estágio da falha. Os logs são transmitidos ao vivo; a documentação da Cloudflare informa que eles não são armazenados. Compartilhe somente essa mensagem resumida, sem URLs de requisições, IPs ou cabeçalhos.

    Esperadotables: 20, triggers: 14 e financialArchiveGap: false. Qualquer outro valor orienta uma correção específica.

2. Inicialize o banco vazio, em ordem

Abra o PowerShell na pasta C:\Users\johny\Desktop\Linux_Flow\github-linux-flow. O Git conectado ao GitHub não autentica o Wrangler na Cloudflare. Execute npx wrangler login --device e conclua a autorização na sua própria conta com 2FA; não envie senha, token ou código de verificação. Depois, npx wrangler whoami deve mostrar a conta correta. O manual do Wrangler explica esse login.

npx wrangler login --device
npx wrangler whoami
npx wrangler d1 info linux-flow-db

Antes de escrever, compare o ID informado por d1 info com o ID do banco aberto no painel: 3d0512f2-340d-44ca-8774-597d8b611f96. Se for diferente, pare. A Cloudflare documenta que --remote --file aplica cada arquivo ao D1 remoto. Na primeira execução, o npx pode pedir para instalar o Wrangler.

Execute uma linha por vez, na ordem abaixo. Aguarde a mensagem de sucesso antes da próxima. Se aparecer erro, pare e compartilhe apenas a mensagem, sem credenciais. A migração 001 contém ALTER TABLE e não deve ser repetida após sucesso.

3. Comprove no domínio público

Na raiz do clone, rode o comando abaixo para conferir site, commit, saúde e ranking em uma única leitura. Ele usa apenas GET, não autentica, não cria dados e mostra somente a quantidade de posições do ranking. Compare o commit exibido com git rev-parse --short HEAD e o deploy no painel. A Cloudflare injeta o SHA do commit no build; o site publica apenas esse identificador, sem segredos. Se alguma etapa falhar, o processo termina com erro e indica este guia.

npm run smoke:live
  1. Saúde da API

    Abra linux-flow.pages.dev/api/health ou rode o comando abaixo. O código atualizado espera 20 tabelas, 14 gatilhos e nenhum pedido existente sem arquivo financeiro. Se ainda der 503, confira o commit publicado, o binding Production e os logs da Function; não adivinhe qual SQL falta. Com todas as estruturas presentes, confira a quantidade de pedidos sem arquivo pela consulta abaixo, sem abrir valores nem referências.

    curl.exe -i https://linux-flow.pages.dev/api/health
    SELECT COUNT(*) AS pedidos_sem_arquivo
FROM pro_requests r LEFT JOIN financial_records f ON f.request_id = r.id
WHERE f.request_id IS NULL;
    EsperadoHTTP 200, {"status":"ready"} e zero pedidos sem arquivo. Isso ainda não prova que perfil, ranking ou Pix estejam funcionando.
  2. Ranking vazio ou autenticado

    Abra https://linux-flow.pages.dev/api/ranking?category=all&level=1&total=10. Sem rodadas publicadas por perfis sincronizados, a resposta deve ser {"ranking":[]}. No PowerShell, teste também a recusa de envio direto sem perfil; esse comando não grava resultado. Na guia Validação, faça depois uma rodada com perfil fictício sincronizado.

    curl.exe -i -X POST https://linux-flow.pages.dev/api/ranking -H "Content-Type: application/json" --data "{}"
    EsperadoGET com HTTP 200 e nenhuma pontuação anônima; POST direto com HTTP 403.
  3. Retenção financeira sem pagamento real

    Use o D1 de Preview e os testes do guia de manutenção. A exclusão de um perfil fictício apaga estudo e ranking, mas mantém o registro do pedido em financial_records e os eventos em financial_events. Não gere Pix real para esse teste.

    EsperadoHistórico com prazo retain_until de pelo menos um ano após o último evento; tentativa de apagá-lo antes do prazo é recusada.
O que me informar

Resultado de /api/health, colunas type e name do inventário, presença das duas colunas indicadas acima, estado do deployment e eventuais mensagens de erro das migrações. Não envie linhas de tabelas com perfis, referências Pix, códigos de acesso ou extratos.

A retenção de um ano é um mínimo técnico definido pelo projeto. A ANPD explica que o prazo apropriado depende da finalidade e de obrigações aplicáveis; confirme o período fiscal com orientação profissional antes da venda.
