Atualize com segurança e saiba voltar.

O código é publicado por Git; o banco tem vida própria. Antes de mexer em esquema, Pix ou dados, saiba qual ambiente está selecionado e registre o motivo da mudança.

Rotina para cada alteração

  1. Revise a diferença

    Atualize código e documentação juntos. Evite segredos em commits, comentários, capturas e logs. Mantenha alterações de esquema em migrações numeradas depois do primeiro deploy.

  2. Execute verificações

    npm test
npm run build
git status --short

    Inspecione dist/ e teste a tela afetada em celular e desktop.

  3. Faça backup antes de mudanças de banco

    O arquivo exportado contém dados pessoais. Use um diretório privado fora do repositório e confirme que a cópia é legível.

    npx wrangler d1 export linux-flow --remote --output=backup.sql

    backup.sql está no .gitignore, mas a prática mais segura é executá-lo fora da pasta do Git.

  4. Publique, observe e registre

    Após push na branch de produção, confira o deploy Pages, as Functions, erros, uso do D1 e os fluxos alterados. Registre decisões em .github/PROJECT_NOTES.md.

Recuperação D1

O D1 oferece Time Travel. No plano Free, a janela informada na documentação atual é de 7 dias. Restaurar substitui o banco atual: não execute esse comando durante uso normal, nem sem avaliar os dados gerados desde o ponto escolhido.

npx wrangler d1 time-travel info linux-flow

Para uma falha só de frontend, prefira reverter o commit e redeploy. Para falha de dados, preserve evidências, exporte o estado atual, avalie o ponto de recuperação e só então restaure com a equipe responsável.

Premium manual: conferência e registro

O usuário apenas declara o pagamento; a API não confirma Pix. Antes de qualquer liberação, encontre a transação no extrato bancário do recebedor, confira valor, perfil, txid e referência. Use o pedido real no Console D1. As duas instruções abaixo não são atômicas; execute uma por vez e confira o número de linhas alteradas.

UPDATE pro_requests
SET status = 'approved',
    approved_at = strftime('%Y-%m-%dT%H:%M:%fZ', 'now')
WHERE id = 'ID_DO_PEDIDO' AND status = 'claimed';

INSERT INTO pro_entitlements (profile_id, request_id, payment_reference)
SELECT profile_id, id, 'REFERENCIA_UNICA_DO_EXTRATO'
FROM pro_requests
WHERE id = 'ID_DO_PEDIDO' AND status = 'approved';

Substitua os dois marcadores e verifique se a referência não foi usada. Se o primeiro UPDATE não alterar exatamente uma linha, pare. Se o INSERT falhar, o pedido ficará aprovado sem acesso; investigue e repita somente a segunda instrução depois de corrigir a causa. Nunca conceda acesso com base em captura de comprovante.

Dados e moderação

  • Revisar pedidos de exclusão e acesso a e-mails de sugestões, após verificar o solicitante.
  • Remover conteúdo abusivo e definir prazos para salas, eventos e grupos antes de operar turmas.
  • Revisar permissões da Cloudflare e do GitHub periodicamente; retirar acesso de quem sair do projeto.
  • Conferir cotas e falhas de API após eventos coletivos.
